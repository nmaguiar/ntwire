Operators

Deploy only the pieces you need.

Most deployments begin with ntwire-server: it owns authentication, grants, local target policy, TLS, and the userspace WireGuard device. Add ntwire-relay only when clients need to reach a server that is behind NAT or otherwise cannot accept direct public connections.

Choose a path

Native peerofficial WireGuard app

These choices affect how clients arrive, not the need for narrow grants and destination policy. Official WireGuard peers are static cryptographic peers; ntwire clients add session authentication, expiry, and revocation.

Deployment options

  • Release binaries: download the server or relay archive matching the host operating system and architecture.
  • Docker Compose: use the repository’s runnable example to start a server and test fixed and SOCKS tunnels.
  • Kubernetes: deploy the provided manifests and use tightly scoped RBAC and NetworkPolicies when relay discovery is enabled.

Production checklist

  • Use a stable server certificate and hostname where possible.
  • Store private keys and administrator tokens outside source control.
  • Grant narrowly, bind sensitive listeners conservatively, and test reload behaviour.
  • Run the documented release gate before publishing a new version.
