Troubleshooting

Let’s get you connected.

Start with the problem you can see. These steps are safe for everyday users; if they do not help, send the requested details to your ntwire administrator.

Installation warnings

macOS says the app cannot be opened because the developer is not identified

ntwire-gui is currently unsigned. Download it only from the official ntwire release, then control-click the app, choose Open, and confirm. This is the expected first-run path for the current release. The GUI app is for Apple-silicon Macs.

Windows SmartScreen warns me before opening the app

Download only from the official ntwire release. Select “More info”, verify the app is ntwire-gui from that release, then choose “Run anyway” if your organisation has approved it.

I do not see a tray icon on Linux

Some Linux desktop environments do not show StatusNotifier tray items by default. On GNOME, install and enable a compatible tray extension, then restart ntwire-gui.

Sign-in and trust

I do not know the server address

Your administrator must provide it. It is usually an HTTPS address. ntwire cannot discover a private server on its own.

I do not have access after adding the server

Confirm the server address and the sign-in method. For SSH, ask the administrator whether they received and approved your public key. For SSO, confirm you signed in with the account your organisation granted.

ntwire asks me to trust a certificate fingerprint

Ask your server administrator to verify the fingerprint before accepting it. A changed fingerprint for a server you used before should be investigated; it can be caused by a server rebuild, but you should not accept it blindly.

My encrypted SSH key asks for a passphrase

Enter the passphrase that protects the private key. It is not your SSO password. If you do not know it, create or obtain a new approved SSH identity from your administrator.

Connected, but I still cannot reach a service

The profile says connected but the address does not open

Open the dashboard and verify the tunnel appears there. Use the local address and port shown by ntwire, not the internal service address. If the tunnel is absent, the server administrator may need to grant it to your identity.

The connection keeps reconnecting or shows a transport warning

Stay connected if possible; ntwire can use a secure fallback when a network blocks UDP. If it continues to fail, try another network and share the displayed connection error and approximate time with your administrator.

The local dashboard does not open

Keep ntwire-gui running and use the “Open dashboard” action from the connected profile. The dashboard link is local to your device and cannot be opened from another computer.

What to send for help

Do not send private keys, passphrases, SSO tokens, or administrator tokens. Instead send your ntwire version, operating system and CPU type, server address (if your policy permits), the visible error, the connection time, and whether another network changes the result.

For deeper operator diagnostics, see the technical documentation and the repository issue tracker.
